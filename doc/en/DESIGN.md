## Design Goals

- [x] No platform signature needed, no ROM rebuild
- [x] Relax permissions only for `com.android.faceunlock` installed on the system partition; checks for all other callers are unchanged
- [x] No persistent foreground notification
- [x] The repo contains no Megvii binaries and no settings education page assets
- [x] Provide a guide for porting to other base images: [porting-guide](porting-guide.md)
- [ ] Verify on devices other than TB321FU
- [ ] `services/build.sh` supports the compressed ART apex (`.capex`) of Android 17

## Architecture

The original ParanoidSense is built together with the ROM: the app is signed with the platform key and runs as `android.uid.system`, and the framework has a matching Sense face provider. On a GSI none of these conditions hold. This project fills them in with three parts:

| Directory | Responsibility |
| --- | --- |
| `services/` | `src/`: Sense framework source; `apply_hooks.py`: smali patches; `build.sh`: generates a new `services.jar` from the base image |
| `sense/` | `app/`: the modified ParanoidSense app (`com.android.faceunlock`); `overlay/`: settings overlay, education page assets are taken from upstream at build time; `build.sh`: builds and signs `FaceUnlock.apk` and `FaceUnlockSettingsOverlay.apk` |
| `module/` | Scripts, properties and permission xml of the KernelSU / Magisk module |
| `image/` | Files used only when building into the system image |
| `scripts/` | `fetch_upstream.sh` fetches upstream, `check_dex.py` checks dex, `pack_module.sh` packs the module |
| `third_party/` | Upstream ParanoidSense fetched by `fetch_upstream.sh`, not committed |
| `out/` | Build output, not committed |
| `doc/` | Project docs and the [porting guide](porting-guide.md) |

### 1. services.jar: add the Sense framework

Following the KLC_OS patch `0009-feat-Add-Face-Unlock-with-ParanoidSense`, the 15 classes it adds (`SenseProvider`, the various `Face*Client`, etc.) are adapted to the target base image's `services.jar`, and compiled into `classes4.dex` together with 3 new classes (`SenseHooks`, `SenseSchedulerFactory`, `SenseCurrentUserRetriever`) and 2 AIDL-generated classes, which is then added to the original jar. The other dex files and resources of the original jar are left untouched.

The Pixel base image's `services.jar` is optimized by R8 and differs from the AOSP source, so the adaptation changed:

- Generics are erased, so base classes use raw types and `getFreshDaemon()` gets a cast
- Inlined constants are replaced with numeric values (`STATE_STARTED=1`, `STATE_STOPPED=4`, `LOCKOUT_NONE/TIMED/PERMANENT=0/1/2`; the first three were checked in the bytecode)
- Many methods went from protected to public, and overriding methods were changed to public accordingly; `scheduleWatchdog`, `scheduleInvalidateAuthenticatorId`, `onAddUnknownTemplate`, `startHalOperation` and `onClientFinished`, which are abstract in the base image, were added
- `BiometricScheduler` is not modified; the base image's existing 5-argument constructor is used with `SenseCurrentUserRetriever`

The original patch's 3 changes to `FaceService` and `AuthService` are changed, at the smali level, to call `SenseHooks`.

### 2. Permissions: allow by caller identity

`USE_BIOMETRIC_INTERNAL` and `MANAGE_BIOMETRIC` are both signature-level (not `signature|privileged`), so the privapp allowlist has no effect on them. `services/apply_hooks.py` reroutes 57 `USE_BIOMETRIC_INTERNAL` checks in the biometric services to `SenseHooks.enforceInternal()` / `hasInternal()`:

| Location | Count |
| --- | --- |
| `*_enforcePermission()` generated by the AIDL `@EnforcePermission`: FaceServiceWrapper 32, BiometricServiceWrapper 17, AuthServiceImpl 3 | 52 |
| Direct checks: `FaceServiceWrapper.addAuthenticatorsRegisteredCallback` 1, `AuthService.checkInternalPermission` 1, `AuthServiceImpl.setActiveUser` 1, `FingerprintService$1.getSensorPropertiesInternal` 2 | 5 |
| Body of `Utils.hasInternalPermission(Context)` | 1 more method |

`SenseHooks` allows the call if any condition is met:

1. The caller is system, root, or system_server itself
2. The caller holds `USE_BIOMETRIC_INTERNAL` or `MANAGE_BIOMETRIC` (original behavior)
3. The caller's uid contains `com.android.faceunlock`, and it carries `FLAG_SYSTEM` and `isPrivilegedApp()`. The package info query is wrapped in `Binder.clearCallingIdentity()`

Condition 3 requires the app to be installed in `/system/priv-app/`; a user-installed app with the same name does not satisfy it.

`apply_hooks.py` can be run repeatedly; after running it checks the whole smali tree, and the literal `USE_BIOMETRIC_INTERNAL` is not allowed to appear again.

### 3. Camera: foreground binding

The CAMERA permission of `com.android.faceunlock` is foreground-only at the appops level. When system_server binds SenseService with only `BIND_AUTO_CREATE`, the process is counted as background once the post-startup grace period passes, and CameraService refuses to open the camera with `has been restricted`; the symptom is that the first few unlocks work and then they stop.

`SenseProvider` now binds with `BIND_AUTO_CREATE | BIND_FOREGROUND_SERVICE | BIND_INCLUDE_CAPABILITIES`: the former raises the bound process to foreground level, and the latter passes system_server's camera capability to it. The app does not call `startForeground`, so there is no persistent notification.

### 4. App

- Removed `sharedUserId="android.uid.system"` and the setupdesign / setupcompat dependencies; the enrollment UI uses standard components
- The app process's classpath has no kotlin-stdlib or `services.jar`, so the Kotlin standard library, the AIDL stubs and `vendorImplPrebuilt.jar` are all compiled into the APK's dex
- Apps under `/system/priv-app` do not extract so files: the 4 Megvii so files are stored uncompressed and page-aligned in the APK, with `extractNativeLibs="false"`, and loaded directly from the APK
- The face unlock entry and animation in Settings are provided by `FaceUnlockSettingsOverlay` (target `com.android.settings`)
- The package name is `com.android.faceunlock`, to avoid detection that treats `co.aospa.sense` as a third-party ROM signature. The manifest still says `co.aospa.sense`, and aapt2 link renames it with `--rename-manifest-package`; the two classes under `co.aospa.sense.util` keep the original package name

### 5. Build checks

d8 **MUST NOT** be given `--no-desugaring`: javac 17 compiles method references to private methods (such as `this::getDaemon`) to invokedynamic, and without desugaring the dex is left with `invoke-custom ... invoke-instance@private`, which makes ART throw `IncompatibleClassChangeError` when it reaches it, so system_server restarts in a loop. `scripts/check_dex.py` checks for leftover invoke-custom, invoke types of private methods, cross-class access to private members and references to nonexistent classes; both `build.sh` scripts run it and fail on any problem. It cannot detect problems caused by R8 inlining, see the constraints below.

### 6. Module

`module/post-fs-data.sh` bind-mounts `services.jar` on its own; the directories that need new files (`priv-app`, `etc/permissions`, `etc/sysconfig`, `product/overlay`) are first copied to tmpfs and then stacked onto system with overlayfs (overlayfs does not accept f2fs on `/data` as lowerdir). It does not depend on meta-overlayfs.
`module/service.sh` disables the module and reboots when it finds system_server started 3 times before boot completes; after boot it waits for pm to be available, then grants CAMERA to `com.android.faceunlock` (with the module method the default-permissions directory does not necessarily exist).

## Design Constraints

- `services.jar` can only be generated from the very base image to be flashed; it **MUST NOT** be mixed between different base images
- `services/src/` is adapted to the `services.jar` of Pixel Tablet AP3A.241005.015. When changing base image, javac errors have to be fixed against the base image's bytecode, for the steps see [porting-guide](porting-guide.md); compiling successfully does not mean it is correct either: R8 may inline calls to some base-class methods, where the new subclass's overrides do not take effect, which can only be seen in the logs on a device
- The permission allowance **MUST NOT** be extended to callers other than the `com.android.faceunlock` system priv-app
- The repo **MUST NOT** contain Megvii's so, jar and model files, settings education page assets, built APKs, or signing keys
- Requires Android 15 (min-api 35), arm64

## Data Design

Runtime data on the device, not in the repo:

| Location | Content |
| --- | --- |
| App data of `com.android.faceunlock` | Face templates and enrollment state. Clearing the app data deletes the faces |
| `/data/adb/modules/faceunlock_gsi/mount.log` | Mount and boot protection log of the module method; when the module is auto-disabled, the crash log is also saved in the module directory |
| `ro.face.sense_service=true` | system_server registers `SenseProvider` based on it |
| `ro.face.sense_service.camera_id` | Optional, specifies the camera used for recognition |
